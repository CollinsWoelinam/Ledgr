# Development guide

Setting up, testing, teaching the parser new messages, and building and publishing releases.

**Contents:** [Setup](#setup) · [Checks](#checks) · [Running the app](#running-the-app) · [Screenshots](#screenshots) · [The parser](#the-parser) · [Release builds](#release-builds) · [Publishing](#publishing-a-release) · [Conventions](#conventions)

## Setup

| You need | Notes |
| --- | --- |
| Node 24 | npm workspaces: `apps/mobile`, `packages/parser` |
| JDK 21 | Android Studio's bundled one works: `export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"` |
| Android SDK | `export ANDROID_HOME=~/Library/Android/sdk`, with `platform-tools` on your `PATH` for `adb` |
| An Android phone | With USB debugging on. SMS reading, encryption and notifications need a real build on a real phone |

```sh
npm install
```

## Checks

```sh
npm test            # parser + app unit tests (Jest)
npm run typecheck   # TypeScript, every workspace
npm run lint        # ESLint (eslint-config-expo)
```

CI runs all three on every push. App tests that touch the database use real SQLite through `node:sqlite` (`src/db/testing/nodeDb.ts`), so migrations and repositories are tested against the same SQL as on the phone.

## Running the app

```sh
cd apps/mobile
npx expo start --go                          # Expo Go, demo data only
npx expo run:android                         # development build on a connected phone
npx expo run:android --variant release       # release build, as users get it
```

- `android/` is generated by `npx expo prebuild` from `app.json` and the config plugins, and is git-ignored. Re-run prebuild after adding a native library or changing `app.json`.
- **Smaller, faster builds:** set `reactNativeArchitectures=arm64-v8a` in `android/gradle.properties` after each prebuild, for a 64-bit phone. CI builds `arm64-v8a,armeabi-v7a`.
- The demo data (`src/demo/seed.ts`) is invented and balanced, so it has no balance gaps; each demo transaction carries the SMS it would have come from, in the wallet's real wording.

### Screenshots

The screenshots in `docs/assets/screens/` come from a separate demo copy of the app, so no real data is ever photographed. `LEDGR_DEMO=1` gives it its own app ID (`com.ledgr.app.demo`, "Ledgr Demo") and storage, so it installs beside the real app:

```sh
LEDGR_DEMO=1 npx expo prebuild -p android --clean && LEDGR_DEMO=1 npx expo run:android --variant release
npx expo prebuild -p android --clean     # afterwards: back to the real app
```

Choose *Try it with demo data*, take each screen in light and dark (`ledgrdemo://insights` and so on open them directly), crop off the status and gesture bars, and save them at 400 px wide under `light/` and `dark/` with the same names.

## The parser

`packages/parser` turns an SMS into a transaction. It has no app dependencies, so it's quick to test.

- `templates/providers.json`: each wallet's sender IDs, and `ignore`, `failed` and `evidence` rules for messages that aren't transactions.
- `templates/<wallet>.json`: one template per message format, a regular expression with named groups (`amount`, `fee`, `tax`, `balance`, `name`, `number`, `ref`, `date`…) and the `{amount}` and `{cur}` macros.
- `fixtures/`: anonymised real messages with the expected result. **Every template must have samples**, and every change must keep them all passing.

### Teaching it a new message

Real SMS stay on your machine: `fixtures/raw/` is git-ignored and never committed.

```sh
cd packages/parser
adb shell "content query --uri content://sms/inbox --projection date:body --where \"address='MobileMoney'\"" > fixtures/raw/MobileMoney.txt
npx tsx scripts/raw-to-json.ts MobileMoney     # adb output → JSON
npx tsx scripts/real-corpus.ts                 # match rate, unread message shapes, balance-chain check
```

1. Add or adjust a template until `real-corpus.ts` shows the message recorded and the balance chain still consistent.
2. `npx tsx scripts/make-fixtures.ts` builds anonymised fixtures: names, numbers, IDs, amounts, dates and references are replaced with fakes in the same format.
3. `npx tsx scripts/check-fixture-leaks.ts` must report **no leaks** before you commit.
4. `npm test`.

Changing the templates changes their revision hash, so the app re-reads the inbox once on next launch and records older messages in the new format too.

## Release builds

Release builds are signed with Ledgr's upload key when it's configured through Gradle properties, and with the debug key otherwise (`apps/mobile/plugins/withReleaseSigning.js`). To use the upload key locally, add to `~/.gradle/gradle.properties`:

```properties
LEDGR_UPLOAD_STORE_FILE=/absolute/path/to/ledgr-upload.keystore
LEDGR_UPLOAD_STORE_PASSWORD=…
LEDGR_UPLOAD_KEY_ALIAS=…
LEDGR_UPLOAD_KEY_PASSWORD=…
```

Keep the keystore and its passwords backed up somewhere safe: every update must be signed with the same key. `*.keystore` files are git-ignored. A phone with a debug-signed Ledgr has to uninstall it, losing its local data, before installing a release-signed one.

## Publishing a release

1. Update `CHANGELOG.md` and the version.
2. Tag and push: `git tag v0.2.0 && git push origin v0.2.0`.
3. `.github/workflows/release.yml` runs the tests, builds the APK with the upload key from four repository secrets, checks it isn't debug-signed, and attaches it to a GitHub Release.

| Secret | Value |
| --- | --- |
| `LEDGR_UPLOAD_KEYSTORE_BASE64` | `base64 -i ledgr-upload.keystore` |
| `LEDGR_UPLOAD_STORE_PASSWORD` | The keystore password |
| `LEDGR_UPLOAD_KEY_ALIAS` | The key's alias |
| `LEDGR_UPLOAD_KEY_PASSWORD` | The key's password |

Without them the workflow stops rather than publish a debug-signed build.

## Conventions

- **Money in pesewas.** Integers in minor units everywhere; format only for display.
- **Requirements by ID.** Code refers to the PRD's user stories and requirements (`US-09`, `FR-2.5`).
- **Database changes are migrations.** Append to `src/db/migrations.ts`; never edit one that has shipped.
- **No real data in the repository.** Only anonymised fixtures and invented demo data.
- **Decisions are recorded** in [`decisions/`](decisions) when they shape the architecture.
